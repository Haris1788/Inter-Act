# INTER.act frontend assets model

This file documents how the frontend renders assets and objects with backend-owned runtime events.

## What is backend-driven vs frontend-driven

Backend remains authoritative for:

- arm angles and arm health
- asset health (`idle`, `busy`, `draining`, `recovering`, `failed`, `stopped`)
- object lifecycle and ownership (`owner_type`, `owner_id`, `event_time`, `event_seq`)
- Socket.IO event stream

Frontend is responsible for:

- drawing scene and handoff zones
- mapping ownership to positions
- client-side animation/transitions
- UI controls for fail/recover/demo actions

## Config source

Assets and geometry come from `/config` generated by `app/models/pipeline_config.py`.

Important config fields consumed by frontend:

- `arms`
- `asset_graph`
- `module_flow_order`
- `intake_zone` and `output_zone`

## Main frontend modules

- `app/static/js/main.js` - app bootstrap and frame loop
- `app/static/js/core/state.js` - local state model, ownership event reconciliation
- `app/static/js/core/render.js` - drawing layers and effects
- `app/static/js/core/socket.js` - Socket.IO integration and sync
- `app/static/js/ui/controls.js` - demo and asset control buttons

## Ownership-driven rendering

Object rendering is resolved from owner fields:

- `owner_type=arm|asset` -> attach to that module
- `owner_type=transfer_point` -> render at boundary position
- `owner_type=zone` -> render in intake/output stacks

For reconnect and out-of-order events:

- stale object updates are ignored using `event_seq`/`event_time`
- when target position is temporarily missing, renderer holds last position to avoid flicker/disappear

## Connection and handoff zone ordering

Connection building in `core/state.js` prefers `module_flow_order` from backend, then falls back to graph links. This keeps handoff zones stable and ordered by topology.

## UI controls

Controls call backend routes:

- demo start/stop
- arm stop/start
- asset fail/recover

UI badge reconciliation includes a visual-only fix: if an arm is moving or carrying an object, stale `draining` display is switched to `busy` until fresh health updates arrive.
